## Concept

This objective is the credential and identity plane: where API keys live in dev and prod, how far one key reaches, how keys rotate and are revoked, who may administer access, and how you later prove which identity did what.

Keep two identities apart. Your **API key** authenticates your application to Anthropic. Your **end user** is authenticated by you, and that identity must travel to every tool call and log line, because the key cannot say which person triggered a request.

**Scope boundary.** The guide places secrets management here in Domain 7, not in <ObjLink id="configuration-management" />, even when the key sits in a settings file; configuration management decides which values each environment uses. Per-request entitlement for agents as a deployment practice is <ObjLink id="guardrails-and-safe-deployment" />. Injection and exfiltration are <ObjLink id="ai-application-security" />. Claude Code permission modes and settings scopes in general are <ObjLink id="claude-code-operation" />.

Not this:
- Settings precedence and model pinning
- Prompt injection defences
- Rate-limit mechanics

<Callout type="key" title="Bound the blast radius before the leak happens">
Keys live in a secret manager and are injected at runtime, never in code, repos, prompts or clients. One key per environment and integration, in separate workspaces with their own limits, so a leaked dev key cannot reach production. On exposure, revoke and replace; deleting the commit is not a fix.
</Callout>

### Secrets and API keys across dev and prod

<SubskillAnchor id="id.secrets" />

**Storage and injection.** Store keys in a secrets manager and inject them at runtime as environment variables; the SDKs read `ANTHROPIC_API_KEY` automatically [Certain]. Never put a key in source, a committed config file, CLAUDE.md, a prompt, a log line, or a client. Anthropic also recommends separate keys per purpose, regular rotation and repository secret scanning; as a GitHub secret scanning partner it automatically deactivates Claude API keys found in public repositories [Certain].

**Client-side code.** A browser or mobile app calls your backend, which authenticates the user, holds the key, and applies per-user authorization and rate limits. Organizations with ZDR cannot use CORS at all and must route browser calls through a backend proxy [Certain].

<Sequence title="Keeping the key off the client" actors={["Browser", "Your backend", "Secret manager", "Claude API"]} messages={[["Your backend", "Secret manager", "fetch key at startup"], ["Secret manager", "Your backend", "key held in memory", "reply"], ["Browser", "Your backend", "request + user session"], ["Your backend", "Your backend", "authenticate user, check entitlement", "note"], ["Your backend", "Claude API", "messages.create with key"], ["Claude API", "Your backend", "response", "reply"], ["Your backend", "Browser", "answer only, never the key", "reply"]]} />

**Workspaces bound a leak.** Every request runs in exactly one workspace. Files, Message Batches and Skills are scoped to the workspace, and prompt caches are isolated per workspace on the Claude API [Certain]. Workspaces carry their own spend and rate limits, set lower than the organization's [Certain]. The documented pattern is separate Development, Staging and Production workspaces [Certain], so a leaked dev key cannot read production files or spend production budget.

**Rotation and revocation.** Rotate by creating a new key, updating the secret manager entry, confirming traffic, then deleting the old key. Disabling is reversible (status `inactive`); deleting is permanent (status `archived`) [Certain]. If rotation needs a code deploy, it will happen late.

**Claude Code.** Keep secrets out of the model's context with `Read` deny rules such as `Read(./.env)` and `Read(./secrets/**)` in settings.json; they also cover recognized commands like `cat` and redirection targets, but not a script that opens files itself, so pair them with the sandbox for OS-level enforcement [Certain]. `apiKeyHelper` runs your executable to fetch the credential from a vault instead of storing it in a file [Certain].

**Exam angle:** cues are "in the bundle", "committed", "dev and prod share", "requires a deploy to rotate". The distractor obfuscates, reverts the commit, or rotates a key that still reaches everything.

### Identity validation and authentication

<SubskillAnchor id="id.validation" />

Validate identity at your edge (SSO, OAuth, session tokens) before any model call, and carry the authenticated user ID through the request. When an agent's tool calls a downstream API, use a credential scoped to that user (a delegated OAuth token or an on-behalf-of exchange), not your application's broad service credential, so the downstream system enforces the user's own permissions. Requests to the Claude API authenticate with `Authorization: Bearer` or the legacy `x-api-key` header, both still supported [Certain].

<PostGuide since="2026-08">
Identity-backed **personal** and **service account** keys now stop working when their owner is removed (legacy workspace keys do not), keys can carry an expiration, **Workload Identity Federation** swaps a cloud or CI identity for short-lived tokens, and **App Attest** gives attested iOS and macOS installs one-hour tokens instead of a shipped key [Certain on the authentication page]. Exam-safe principles are unchanged: no static key on a client, one identity per workload.
</PostGuide>

**Exam angle:** cues are "which employee", "on behalf of", "the agent calls the CRM". The distractor uses the app's own credential for every user, or treats the API key as the user's identity.

### Access approval and level verification

<SubskillAnchor id="id.approval" />

Platform access is role-based: only organization admins manage users and create workspaces, and organization users and developers must be added to each workspace with a role such as Workspace User (playground only), Developer (create keys, use the API) or Admin [Certain].

**Admin API keys** start with `sk-ant-admin`, can be provisioned only by organization admins, and drive the Admin API: members, invites, workspaces and API keys [Certain]. The Admin API cannot create new API keys; it can read, rename and change the status of existing ones [Certain]. Workspace-scoped keys do not work on Admin API endpoints [Certain]. Treat the admin key as the crown jewel: separate secret, separate tooling, never in an inference service.

In your application, verify the level at the moment of action: re-read the user's current role per request and require step-up approval for consequential operations.

**Exam angle:** cues are "automate onboarding", "deactivate a key", "only admins". The distractor hands an inference key admin duties or an app server the admin key.

### Authorized access monitoring

<SubskillAnchor id="id.monitoring" />

Monitor at three levels:

| Level | Tool | Answers |
|---|---|---|
| Platform | Usage and Cost API (Admin credentials), filter or group by API key, workspace, model; data usually within 5 minutes [Certain] | Which key or workspace drove this usage? |
| Request | `request-id` and `anthropic-workspace-id` response headers [Certain] | Which workspace did this exact call run in? |
| Application | Your own audit log: end user, credential, tool, resource, outcome | Which person did what to which record? |

Audit keys periodically and remove unused ones. For Claude Code fleets, OpenTelemetry (`CLAUDE_CODE_ENABLE_TELEMETRY=1`, settable in managed settings) exports tool permission decisions with user attributes, prompt text redacted by default [Certain]. One key per integration is what makes platform reports attributable.

**Exam angle:** cues are "which integration", "cost spike", "who approved". The distractor logs only the service or a shared key.

## Decision table

| If the stem says... | Choose | Why the runner-up loses |
|---|---|---|
| A mobile or browser app calls Claude directly | Backend proxy holding the key and authenticating the user | An obfuscated key in the bundle is compromised on ship |
| A key was pushed to a public repo, then reverted | Revoke and replace the key now; clean history afterwards | Deleting the commit leaves the key valid in every clone and cache |
| A leaked dev key must not reach production | Separate workspaces per environment, each with its own keys and limits | Rotating a shared key more often shortens the window but keeps the reach |
| A script must deactivate keys and manage workspace members | Admin API key, held only by admin tooling | A regular workspace key is rejected by Admin API endpoints |
| Finance needs to know which integration caused a cost spike | One key per integration, Usage API grouped by API key | A shared key cannot be attributed to anyone |
| Claude Code must never read the project's .env | `Read` deny rules in settings.json, sandbox for subprocesses | A CLAUDE.md instruction is advisory |
| An agent's tool queries the CRM for the signed-in user | User-scoped delegated token, checked per call | The application's service credential exceeds the user's rights |
| Rotating the key requires rebuilding the container image | Fetch from the secret manager at runtime | A baked-in key guarantees late rotation |

## Worked walkthrough

<Walkthrough title="Scenario: a notebook key that reached production">

<Step title="Read the scenario">
A data team builds a Claude-powered enrichment job. Engineers prototype in notebooks with the same API key the production job uses, and production uploads customer files through the Files API. After a key turns up in a shared notebook export, the security lead requires that **a leaked development credential can never read production files or spend production budget**. What change meets this?
</Step>

<Step title="Find the constraint">
"Can never read production files or spend production budget" is about **reach**, not storage or lifetime. Whatever the dev credential is, it must be structurally unable to touch production resources and limits.
</Step>

<Step title="Eliminate the storage and lifetime options">
"Move the key into a Databricks secret scope" fixes where the key lives, but it is still the production key. "Rotate the key monthly" shortens how long a leak works, not what it reaches.
</Step>

<Step title="Eliminate the blunt limit">
"Lower the organization-wide spend limit" caps money for everyone, throttles production too, and does nothing for file access.
</Step>

<Step title="Choose">
Create separate Development and Production workspaces, issue keys per workspace, and set a low spend limit on Development. Files, batches and skills are workspace-scoped, so a dev key cannot list or read production files, and its spending stops at the dev cap.
</Step>

<Step title="The deciding cue">
The deciding cue was **"can never read production files or spend production budget"**: a reach requirement across environments resolves to workspace separation with per-workspace keys and limits, not to better storage or faster rotation.
</Step>

</Walkthrough>

## Code

**Key from the environment, failing fast, with an attributable audit line.** The key is injected by the secret manager; the code never logs it, and records end user, workspace and request ID for every call.

```python
import json
import os
import anthropic

api_key = os.environ.get("ANTHROPIC_API_KEY")
if not api_key:
    raise SystemExit("ANTHROPIC_API_KEY not set: inject it from the secret manager, never hardcode it")
client = anthropic.Anthropic(api_key=api_key)


def text_of(msg) -> str:
    return "".join(b.text for b in msg.content if b.type == "text")


def ask(end_user_id: str, question: str) -> str:
    raw = client.messages.with_raw_response.create(
        model="claude-sonnet-5-5",
        max_tokens=500,
        messages=[{"role": "user", "content": question}],
    )
    msg = raw.parse()
    audit = {
        "end_user": end_user_id,  # your identity, not Anthropic's
        "workspace": raw.headers.get("anthropic-workspace-id"),
        "request_id": raw.headers.get("request-id"),
        "output_tokens": msg.usage.output_tokens,
    }
    print(json.dumps(audit))  # ship to your audit sink; never include the key
    return text_of(msg)


print(ask("emp_1042", "Summarize our expense policy in one sentence."))
```

```typescript
import Anthropic from "@anthropic-ai/sdk";

const apiKey = process.env.ANTHROPIC_API_KEY;
if (!apiKey) throw new Error("ANTHROPIC_API_KEY not set: inject it from the secret manager, never hardcode it");
const client = new Anthropic({ apiKey });

function textOf(msg: Anthropic.Message): string {
  return msg.content.filter((b): b is Anthropic.TextBlock => b.type === "text").map((b) => b.text).join("");
}

async function ask(endUserId: string, question: string): Promise<string> {
  const { data: msg, response } = await client.messages
    .create({ model: "claude-sonnet-5-5", max_tokens: 500, messages: [{ role: "user", content: question }] })
    .withResponse();
  const audit = {
    end_user: endUserId, // your identity, not Anthropic's
    workspace: response.headers.get("anthropic-workspace-id"),
    request_id: response.headers.get("request-id"),
    output_tokens: msg.usage.output_tokens,
  };
  console.log(JSON.stringify(audit)); // ship to your audit sink; never include the key
  return textOf(msg);
}

console.log(await ask("emp_1042", "Summarize our expense policy in one sentence."));
```

**Admin tooling: audit active keys and deactivate one.** A separate admin credential, never deployed with the application. The SDK exposes the Admin API under `beta.organization` [Likely: namespace may move].

```python
import os
import anthropic

admin = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_ADMIN_KEY"])  # sk-ant-admin..., admin tooling only

for key in admin.beta.organization.api_keys.list(limit=50, status="active"):
    note = "no expiry" if getattr(key, "expires_at", None) is None else f"expires {key.expires_at}"
    print(f"{key.id}  {key.name}  {note}")

revoke_id = os.environ.get("REVOKE_KEY_ID")
if revoke_id:
    updated = admin.beta.organization.api_keys.update(revoke_id, status="inactive")  # reversible; delete in Console is permanent
    print(f"{updated.id} is now {updated.status}")
```

```typescript
import Anthropic from "@anthropic-ai/sdk";

const admin = new Anthropic({ apiKey: process.env.ANTHROPIC_ADMIN_KEY }); // sk-ant-admin..., admin tooling only

for await (const key of admin.beta.organization.apiKeys.list({ limit: 50, status: "active" })) {
  const expires = (key as { expires_at?: string | null }).expires_at;
  console.log(`${key.id}  ${key.name}  ${expires ? `expires ${expires}` : "no expiry"}`);
}

const revokeId = process.env.REVOKE_KEY_ID;
if (revokeId) {
  const updated = await admin.beta.organization.apiKeys.update(revokeId, { status: "inactive" }); // reversible
  console.log(`${updated.id} is now ${updated.status}`);
}
```

**Claude Code: secrets never enter the context.** Deny rules are enforced by the harness; the hook blocks Bash commands that touch secret paths or dump the environment, exiting 2 so the call stops and the reason goes back to Claude.

```json
{
  "permissions": {
    "deny": ["Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)"]
  },
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash", "hooks": [{ "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/block-secrets.sh" }] }
    ]
  }
}
```

```bash
#!/usr/bin/env bash
# .claude/hooks/block-secrets.sh: reads the PreToolUse JSON on stdin
cmd=$(jq -r '.tool_input.command // ""')
if printf '%s' "$cmd" | grep -Eq '(\.env|secrets/|printenv|ANTHROPIC_API_KEY)'; then
  echo "Blocked: command touches secrets or environment variables" >&2
  exit 2
fi
exit 0
```
